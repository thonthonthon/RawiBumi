RawiBumi manual

Bahasa Indonesia Back to RawiBumi

RawiBumi designs and simulates grid-connected PV on roofs and the ground. You draw the roofs, fill them with modules, group them into systems, wire strings to inverters, choose a weather year, run an hourly simulation of a full year with near shading, then read the results and export a report. This manual explains how to operate every step and what each setting and result means. The software is a beta; known limits are in chapter 19.

1. Getting started

The start screen

The start screen lists the saved projects (name, location, time zone) and shows how many modules and inverters the component library holds. Click a project to open it. Each row also has Rename, Delete (you type the exact name to confirm; this removes the project, its runs and its weather), Export… and Backups….

New project: enter a name, the latitude and longitude (click the map or type them), the elevation and the time zone (an IANA name such as Asia/Jakarta). Choose where to start in: a blank engineering plane (an empty grid) or a map overlay (you draw over a map). Press Create project.

Project files and backups

  • Export (start screen Export…, or the Report & export step): one .rawibumi file with the project, its weather and its overlay images, optionally with saved results (the file is then larger). Use it to keep a copy or move the project to another RawiBumi.
  • Import project (start screen): restores such a file. If the same project exists, you are asked whether to replace it; the current one is backed up first. Runs that arrive by import are labelled Imported: not computed by this installation.
  • Backups: every save is kept (the newest 20), plus a protected copy before any import, restore or upgrade. Open Backups… to restore one.

Ctrl+Z undoes; Ctrl+Shift+Z or Ctrl+Y redoes. Every engine edit (a roof, a fill, a table move, a string change) is one step. The engine keeps the last 10 steps of each project, also after you reload the page.

Saving

Edits are saved as you make them; there is nothing to save by hand. Forms with an Apply or Save button keep a draft until you press it.

3. Conventions and units

  • Plan coordinates are metres: X to the east, Y to the north, measured from the scene origin, which the plan marks with labelled X and Y arrows.
  • Azimuth is the direction a surface or module faces: 0° north, 90° east, 180° south, 270° west, clockwise. In Indonesia, south of the equator, modules facing roughly north (azimuth near 0°) usually yield the most.
  • Tilt is the angle from horizontal: 0° lies flat, 90° is vertical.
  • Heights: a roof's height is its level above the ground. An obstacle has a base elevation (where it starts) and a height (how tall it is).
  • Numbers use a point for decimals. Height and elevation fields in the inspector save when you press Enter or leave the field; Esc cancels; the up and down arrows step the value at once.
  • Typed input while drawing: x,y for a point, @dx,dy relative to the last point, d<bearing for a distance along a bearing (0° north, clockwise), or a single length along the cursor direction. Units m, cm and mm and arithmetic such as 12.5+0.3 work. The comma separates x and y, so decimals take a point.
  • Energy is in kWh or MWh; power in kW (AC) or kWp (DC at standard test conditions).

Address

RawiBumi looks the address up from the coordinates (OpenStreetMap Nominatim; you can switch the lookup off). Edit it freely: your text is never replaced. It is saved with the project and printed on the report cover.

System summary

Installation type (on-grid, on-grid with zero export, off-grid, hybrid with battery, or not given) and the battery (BESS) energy and power. They appear on the report cover. They are not simulated: RawiBumi simulates grid-connected PV only.

Imagery

  • Basemap: streets; satellite or hybrid after you set up an imagery provider you are licensed to use (an https tile address containing {z}, {x} and {y}; its key stays in your browser and is never saved in a project).
  • Image overlay: upload an aerial photo, drone orthophoto or drawing (PNG, JPEG or WebP, up to 10 MB and 8,192 px per side). Drag it to move, drag a corner to scale (Shift keeps the proportions), use the round handle to rotate, or type its resolution, rotation and top-left position.
  • Calibrate with two points: click two points a known distance apart on the image, then type that distance. The image is scaled to match.
  • Lock overlay when it is right, so clicks pass through to your drawing. Lower the overlay opacity to see your design over it.
Imagery is context only: dimensions you type or survey always win over traced ones. Your uploaded overlay appears in the report's layout figure; satellite tiles never do.

5. Step 2 · Components (Alt+2)

  • In this project: the modules and inverters the design uses. The project keeps its own copy of each (a pinned revision), so later library changes never alter it silently.
  • Library: filter by type (modules or inverters), brand and status, or search by model. Long lists are shortened; narrow the filters to see the rest.
  • Import PAN / OND: add your own PVsyst component files (up to 2 MiB and 5,000 lines each). A refused file shows the reason. Missing inverter datasheet values can be completed with a cited source.
  • A PAN file's light-induced degradation (LID) value is offered as a suggestion and not applied: the loss settings keep LID at 0 % until you change it.

6. Step 3 · Scene (Alt+3)

In the Inspector, choose one of nine reference points on the object’s own box (u follows the first edge; v is 90° counter-clockwise). The choice is saved; the default is start/start (minimum u and v). Position X/Y places that point in scene metres. Move reference point to origin places it at (0, 0). Orientation is the compass bearing of u (0° north, clockwise), and rotates about the reference point. Move by ΔX/ΔY can use scene or own axes. Rectangle Length/Width follow u/v and keep the reference point fixed. Relative rotation can use the centre or reference point.

The scene is the 3D model of everything that holds or shades the modules: roofs, holes, obstacles and keep-out zones.

Applying

Apply fill places the modules; one fill is one undo step. If the roof already has a PV field, Apply fill asks you to confirm that it replaces the existing layout. The confirmation shows the module count and STC power before and after, and the strings that will be deleted.

The PV fields list

Each field shows one summary line: modules, kWp, tilt and azimuth. Open Details for the roof, the table count, the orientation and any notes. Re-fill loads the field's stored settings into the form so you can change them and apply again. Delete field shows what is removed (modules, strings) before you confirm.

Editing tables

Click a module to select it; drag it to move its whole table. You can move selected tables by an exact distance east and north, delete them, or remove single modules: Delete removes the selected modules and Shift+Delete their tables. Every edit pins the tables it touches, and a later re-fill keeps pinned tables where they are. Unpin a table to let the fill place it again.

8. Step 5 · Systems (Alt+5)

Systems organises the design before detailed wiring: which roofs form a building, how far apart the buildings are, which modules face the same way, and which inverters serve which roofs.

Buildings

Press Use suggested buildings to group touching or nearby roofs. Rename a building, merge two, or ungroup a roof. Buildings organise the design and the report; they do not change the physics.

Distances

The nearest edge-to-edge distance between buildings. Distances above the warning threshold (50 m by default) are flagged, for example because of long DC cables. It is a warning, never a block.

Orientation groups

Modules grouped by the direction they face, within the orientation tolerance (at most 1° between module normals; set in Electrical).

Inverters

  1. Choose an inverter model and a count, then Add inverters.
  2. Choose which roofs each inverter serves, then Save area.
  3. Read the sizing help: the valid string length range (from the module's cold open-circuit voltage and the inverter's voltage limits), how many inverters of this model reach your DC/AC target, each MPPT's inputs, and whether short-circuit current limits an MPPT's number of strings.
  4. Fill each MPPT's row: the source roof (or any roof this inverter serves), the string length and the number of strings. Or press Suggest for an engine-sized layout and adjust it.
  5. Check the live engine checks under the table, then press Apply MPPT layout.

Applying keeps existing strings that still fit (same MPPT and length) and re-strings the rest, using the modules of the replaced strings and any unstrung modules.

Expert notation

The same layout as text. Strings on one MPPT are separated by commas, MPPTs by semicolons: 16,16 ; 16 is two strings of 16 modules on MPPT 1 and one on MPPT 2. 0 leaves an input empty; 3x(16,0) repeats a pattern.

If an MPPT combines roof orientations, RawiBumi simulates it physically, and the extra loss appears as Orientation mismatch in Results.

9. Step 6 · Electrical (Alt+6)

Here you wire modules into strings and connect the strings to inverter MPPTs. The plan colours modules by MPPT; unstrung modules are hatched.

The target MPPT

New strings and the Assign brush go to the target MPPT. Step through MPPTs with [ and ], pick one within the inverter with 1–9, or click an MPPT in the topology tree.

Working with a selection

The Selection section summarises what you selected: modules, how many are not in a string, and whole strings. It offers String the selection (strings of a chosen length), Assign strings to target, Unassign, Delete strings and Replicate pattern (copies one table's wiring onto every identical, unwired table). Right-click unstrung modules for Add n to S00x or New string of n on MPPT….

Uniform strings

Creates strings of a fixed number of modules for one PV field or for all unstrung modules, row by row or serpentine (every other row reversed, which shortens string cable), optionally allowing a shorter last string.

Topology tree and checks

The tree lists inverters, MPPTs and strings. Each string and MPPT has live checks: Pass, Warning, Fails or Not available, with the string's operating voltage range against the MPPT window.

Rules that block a run
  • The string's open-circuit voltage at the coldest design cell temperature exceeds the inverter's maximum DC voltage. This can damage the inverter on a cold morning before it starts tracking. Shorten the string.
  • The string's operating voltage at the hottest or coldest design temperature leaves the MPPT window. Change the string length or the inverter.
  • Too many strings in parallel for the MPPT's operating or short-circuit current.

Orientation rule

The orientation tolerance (0–1°) is the largest angle between module normals that still counts as one orientation on an MPPT. You may accept a mixed MPPT with an override and a written reason; it is then simulated with its mixed orientations.

Single-line diagram

Switch the stage to SLD to see inverters, MPPTs and strings as a diagram.

11. Step 8 · Losses & grid (Alt+8)

Losses and settings

Every value starts from RawiBumi's recommended defaults; edit them to match your project. Changes apply to future runs only, and each run records the settings it used.

New projects use recommended_defaults.v2: an explicit LID override applies to every circuit; otherwise each circuit uses its module file's finite LID fraction in [0, 1). Missing or invalid values fall back to generic starting values: 0.5 % for TOPCon, HJT, heterojunction or IBC technology; 1.5 % for other crystalline silicon and unknown technology; 0 % for thin film. These are starting values, not measurements: check the datasheet. Clear the input to restore automatic LID. Each run records the per-circuit value and source. Earlier v1 projects retain LID 0 % unless overridden; “Use the current defaults” switches to v2 in one undoable save, preserving overrides. Saved results stay unchanged.

Shading accuracy

Standard (recommended) samples the sky in 48 × 12 sectors, with matching horizon and ground sampling. High samples more finely and takes longer, especially with detailed electrical shading.

12. Step 9 · Simulate (Alt+9)

Preflight

Preflight lists what blocks a run (for example no weather, required modules not strung, or a voltage rule failure) and what only warns (Before you run). Only saved engine data is simulated; unapplied drafts never enter the physics.

Execution

OptionMeaning
Existing geometry executionThe standard path: geometric near shading of beam, sky and ground light on each group of modules.
Detailed electrical shadingAlso models the electrical effect of partial shading through module substrings and bypass diodes (slower). The fallback policy decides whether a lower fidelity may be used when that detail is unavailable; fail closed refuses instead.

Press Validate and run. A run takes from under a minute to many minutes, depending on the number of modules and obstacles and the accuracy level. Wait for it to finish before editing; on a slow connection the page keeps checking until the run is done.

Run history

Lists the project's runs. A run from an earlier design is marked earlier design: run again to update it.

13. Step 10 · Results (Alt+0)

Key figures

AC energy (Reference Production)
The PV-attributable AC energy at the point of common coupling (PCC) over the simulated period, after every modelled loss.
Specific yield
Energy ÷ installed DC capacity, in kWh/kWp, which makes plants of different sizes comparable.
Performance ratio (PR)
Energy ÷ (simulated kWp × unshaded plane-of-array irradiation): how much of the sunlight's potential reached the grid. Well-designed rooftops are often around 0.75–0.85.
Peak AC
The highest AC power in the period.
Clipping
Energy lost because the inverter limited its output to its rated power.

Views

  • Monthly: energy, performance (specific yield and PR per month), losses and meteorology per month.
  • Loss waterfall: from the reference energy to the AC energy, stage by stage; it always reconciles (chapter 15).
  • Heatmap: mean power, or cell temperature, by week and hour.
  • Daily profile: the average day of each month.
  • Assumptions: the settings this run used.

Below them: the inverter results (energy, voltage-window and start-up losses per inverter), mixed- orientation results where they apply, the readiness warnings recorded when the run started, and the result checks, automatic rules run on the result. A failed blocking rule stops the report.

Annual P50–P95

The simulation itself has no uncertainty. Enter your uncertainty assumptions: for each term, its σ and unit, a source and a justification. Terms in one double-count group must be combined first. State whether the terms are independent or give a correlation matrix. RawiBumi then computes P50 to P95, the annual energy exceeded with that probability. P99 is not given by this method, and RawiBumi offers no default percentages.

15. The loss chain explained

The loss waterfall starts from the energy the modules would give at their rated efficiency with the sunlight reaching the array, and subtracts each effect in turn:

StageWhat it is
Geometric shadingLight blocked by obstacles, roofs and other rows: beam, sky and ground light.
Orientation mismatchThe extra loss when one MPPT combines modules facing different ways.
SoilingDirt on the glass.
Module operating effectsTemperature and low-irradiance behaviour of the module model.
LIDLight-induced degradation.
Module qualityThe module's tolerance from its datasheet; negative means a gain.
Module and string mismatchElectrical spread between modules and between strings.
DegradationAgeing in the simulated operating year.
DC wiringResistive loss in the DC cables.
InverterConversion efficiency at each power and voltage, operation at the edge of the voltage window, the start-up threshold, and clipping at the power limit.
AC wiring and plant AC wiringResistive loss in the AC cables.
Transformer iron and copperWhen a transformer is enabled.
UnavailabilityWhen set.

In every hour, the reference energy less all losses equals the AC energy, or the run fails.

16. Glossary

STC
Standard test conditions: 1,000 W/m² and 25 °C cell temperature. Module power (Wp) is rated at STC.
kWp
DC capacity: the sum of the modules' STC power.
GHI, DNI, DHI
Global horizontal, direct normal and diffuse horizontal irradiance.
POA
Plane of array: the irradiance on the tilted module surface.
IAM
Incidence-angle modifier: the reflection loss when light hits the glass at an angle.
String
Modules wired in series; their voltages add up.
MPPT
Maximum power point tracker: an inverter input that runs its strings at their best voltage. Strings in parallel on one MPPT should match in length and orientation.
Voc, Vmp, Isc, Imp
Open-circuit voltage, voltage at maximum power, short-circuit current and current at maximum power. Voc rises in the cold, which is why the coldest temperature sets the longest safe string.
DC/AC ratio
DC capacity ÷ inverter AC rating. Above 1, the inverter clips some peak power.
Clipping
Energy lost when the DC power exceeds what the inverter can convert.
PCC
Point of common coupling: where the plant connects to the grid.
GCR
Ground-coverage ratio: the tables' slant depth ÷ the row pitch.
Pitch
The distance from the front of one table to the front of the next.
Albedo
The fraction of light the ground reflects.
Uc, Uv
The module's heat-loss coefficients: constant and wind-dependent.
TMY
Typical meteorological year: a year assembled from typical months.
P50, P90
The annual energy exceeded with 50 % and 90 % probability.

18. Messages and troubleshooting

A step shows Blocked
Open it: the blocking finding is listed at the top, or in Simulate → Preflight. Fix that first.
"Unable to detect weather format"
The file is not a supported format (chapter 10). From Meteonorm or PVsyst, export TMY3 or "PVsyst Standard" CSV.
"Not enough unstrung modules for an n-module string"
The layout asks for more modules than are free in the inverter's area. Lower the string length or count, or widen the roofs the inverter serves.
A string voltage check fails
Shorten the string if its cold Voc is above the inverter maximum; change the length or the inverter if it leaves the MPPT window.
"These results are from an earlier design"
The design changed after the run. Run again for current results and a report.
A number does not save
Press Enter or leave the field; in forms, press the form's Apply or Save.
Undo does nothing
There is no earlier step for this project (the engine keeps 10), or the server was restarted.
"The project changed elsewhere"
Someone else in your group edited the same project; the latest version has loaded. Repeat your edit.

19. Known limits

  • RawiBumi has not yet been compared with measured plant data. It agrees with PVsyst within a fraction of a percent on two real shaded projects; PVsyst is a benchmark, not the truth.
  • Not modelled: batteries, loads and export limits, far-horizon shading (there is no horizon profile yet), time steps shorter than an hour, reactive power, inverter temperature behaviour, and daylight-saving time zones.
  • The default losses are starting values; review them for each site.
  • Undo keeps the last 10 engine steps per project and is cleared if the server restarts.
  • Rotated rectangles: set lengths before rotating (chapter 6).

20. Your data, the beta and feedback

On your own computer, everything stays in the app's data folder (var/): projects, weather, runs, imagery and the component library. Nothing is sent anywhere except the online services you use from the app: Open-Meteo when you acquire a weather year, Nominatim when you search an address, and OpenFreeMap while the map is shown. Back up the data folder to back up your work.

On a test service you were invited to, you sign in with an access code and your email. The code binds to the first email used with it, so use the same email each time; it stops working when the test window closes. The organiser keeps your group's projects and uploaded files and an access log (email, time, pages and actions), as the sign-in page states. Everyone in your group sees the group's projects, so do not upload confidential client data. You can ask the organiser to delete your data at any time.

RawiBumi is a beta: there is no warranty, and results must be reviewed by an engineer before they are relied on.

Feedback: say which step, what you did, what happened and what you expected, with a screenshot if you can. Send it as an issue on the project's GitHub page, or to the organiser of your test.
