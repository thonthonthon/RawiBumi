## 4. OND import and efficiency semantics

The route is raw parse → evidence-led scalar mapping → cross-field assembly → candidate validation/capabilities/schema readiness → optional finalization. `components/panond_raw.py:98`, `parse_panond_text()`, preserves ordered raw fields, duplicate keys and source text; `components/ond/mapper.py:13` applies the mapping ledger through `components/mapping.py`. `components/candidates.py:360` receives identity/revision/source ID explicitly from the caller, not from an implicit manufacturer revision scheme. `:380` assembles semantics, `:382` validates, `:398` derives flags. Finalization (`:431`) checks schema and errors and labels `auto_validated`; it does not certify measured performance, manufacturer approval or design readiness.

`components/ond/semantics.py:64`, `_assemble_efficiency_model()`, accepts only `POutf_PIn`, exactly three voltage anchors, and complete `NPtsEff` point sets. It computes efficiency=Pout/Pin (zero for zero input), preserves derivation inputs and produces `dc_input_to_ac_output` curves. Unsupported/incomplete structures warn rather than being silently coerced. Eight active points are consumed here; padded points 9–11 are excluded by `NPtsEff=8`. The separate base `ProfilPIO` is not substituted for the voltage profiles. `TCubicProfile`, `Mode`, `LastCompile` and padding do not cause execution of a PVsyst cubic compiler.

Units are field-specific: nominal/max AC and PV-array ratings use kW→W (`components/ond/mapping-ledger.yaml:186`, `:208`, `:316`, `:338`); Pin/Pout pairs are W/W (`:598`); PSeuil and Night_Loss are W (`:163`, `:461`); efficiencies in percent become fractions (`:382`). `UnitAffEnum=kW` in the file is not applied globally to already-W curve pairs. No nameplate-normalized curve power is assumed.

The actual runtime at `engine/inverter/model.py:67`, `_curve_ac_output_w()`, sorts points and requires finite, nonnegative powers and strictly increasing input. It linearly interpolates **Pin/Pout**, holds first output below the first point, holds endpoint efficiency above the last, and bounds Pout to [0,Pin]. Voltage is clamped to the anchor range and nearest-three quadratic interpolation is bounded to [0,Pin] (`:104`); two anchors use linear interpolation. All Huawei anchor curves are identical, so the B2 voltage interpolation has no effect. Multi-MPPT efficiency evaluates each tracker voltage at total inverter DC input and weights by tracker power (`:147`), avoiding repeated fixed losses per tracker.

`simulate_voltage_dependent_inverter()` (`:341`) checks absolute Voc, physical current if supplied, and MPPT Vmp window; rejected voltage power is a separate loss. Converter activation requires accepted power **strictly greater** than startup power or fallback minimum input power; equal/below threshold loses all accepted DC before conversion. There is no separate verified startup-voltage/hysteresis implementation demonstrated by this path. Night consumption applies to zero raw DC; standby to positive raw DC with inactive converter; absent consumption values default to zero. An efficiency-model `startup_loss_w` datum is not an additional subtraction in this path. Conversion, AC clipping and self-consumption remain distinct; net AC can be negative at night.

`_ac_power_limit()` (`:221`) defaults to maximum AC when runtime inverter temperature is absent. Supplied temperature requires complete breakpoints and explicitly resolved compatible basis; linear segments interpolate source power limits, hold the last verified point above its temperature, and fail at the absolute limit rather than invent zero output. Detailed downstream does not supply inverter temperature in B2 (accepted RB-POST3D-03 §4); derating-ready is not evidence derating ran.

Source first points `(500,0)` and `(3000,2831.2)` (`OND:88`) produce marginal slope 1.13248. Thus `Pout=1.13248*(Pin−500)` in that segment, while Pout/Pin remains below one. A slope above one is not efficiency above one or proof of an engine defect. RB-POST3D-03 §§5–7 shows B2's 15 converting intervals at 533–1427 W use this segment, explaining energy-weighted efficiency 54.044% and PR 0.381902 with no conversion normalization defect demonstrated. These retained arithmetic results were not recomputed here.

**Further semantic validation is needed** before claiming PVsyst compatibility or physical low-load accuracy: obtain evidence for the intended source-profile interpolation, source units/profile mode of the selected future file, low-load/voltage operating domain, thresholds, startup/standby conventions and temperature basis. Current bounded-linear/quadratic behavior is confirmed repository behavior; general external PVsyst equivalence is unsupported. No external acquisition is performed or necessary to document this boundary.
