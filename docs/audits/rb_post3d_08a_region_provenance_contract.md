## 1. Executive engineering decision

Propose a narrowly gated **numerical-assumption evidence branch**, alongside the existing validated branch. Do not label assumed Jinko regional wiring or parameters as validated. Keep the module's original source/model validation intact and authorize only Level-2 numerical experimentation with deliberate opt-in. This document proposes subsequent work; it implements and authorizes no production amendment.

The exact obstacle is two independent contracts: trusted internal topology and validated regional parameterization. Explicit bypass assumptions already exist but do not satisfy either contract. Merely adding `--allow-synthetic-regions` to a tool, setting capability booleans, or relabeling parameters `derived_validated` cannot honestly cross this boundary.

Smallest recommended representation: retain existing topology `inferred` / `unverified` states and existing executable parameter definitions; put a strictly checked, revision-bound assumption declaration in their existing `metadata`. Amend only the parameterization-evidence schema with a separately versioned assumption branch. Keep a default-deny policy argument at capability, pinning and executable regional-model boundaries. Store the affirmative permission in `scientific_options`, not discarded `execution_options`. Preserve the existing validated capability result and bytes when no assumption path is requested.

Evidence classification, numerical consistency and execution permission are separate facts. A consistency test passing does not validate manufacturer connectivity. Independent package verification means integrity and contract verification, not physical validation.

## 4. Minimal numerical-assumption policy

The proposed subsequent schema amendment is an evidence v0.2 branch accepted alongside the exact legacy v0.1 branch, with `contract_version=0.1` retained for unchanged circuit/units conventions. New branch fields: `evidence_class=NUMERICAL_ASSUMPTION`, `parameterization_provenance=simulation_assumption`, `verification_state=not_applicable`, `validation_status=not_applicable`, `validation_record_id=null`; retain all common binding/model/payload/source fields. Require `parameterization_revision_id` and a typed `assumption_declaration`. These names are proposals, not existing enum values. Version branching must reject v0.1 payloads carrying the new semantics and reject v0.2 records claiming validated or manufacturer states. No widening of the legacy trusted sets.

The declaration contains:

- Distinct `assumption_id`, `assumption_revision_id`, author/rationale and `assumption_source_id`; all nonempty, immutable per revision. Assumption source is `user_input` or `manual_entry`, with `manufacturer=null`, explicit title/notes and `file_hash` matching canonical declaration bytes excluding its own digest. Original PAN source ID, filename and existing hash remain separate and unchanged; retain OND/datasheet source identities too.
- Exact module, topology and parameterization revision IDs; exact topology digest (`canonical_topology_asset_sha256`) and `parameterization_payload_sha256`; model ID/version; original source IDs/digests; referenced bypass assumption IDs. Include an assumption-payload digest computed excluding its own digest. Avoid circular hashing: put assumption identity/revision in topology/definition metadata, but keep their digests in the evidence declaration, not inside the topology it hashes.
- Declared region UV geometry, wiring rationale and parameter derivation policy by reference to the fully pinned topology/definition. These asset payloads are authoritative parameter values; declarations cannot supply contradictory shadow values.
- A consistency record with policy ID/version, deterministic condition grid, numerical tolerances, measured residuals and pass/fail, bound to the same asset/model digests. This is a numerical-consistency record, never `validation_record_id`. Verifier recomputes the tests; a stored `passed` flag alone is insufficient.
- Explicit limitations: assumed manufacturer connectivity, assumed reverse behavior and diode parameters where applicable; single module temperature; sampled IV/ideal global MPPT and existing downstream limitations; no manufacturer, electrical-design, physical-yield or general PVsyst-equivalence validation.

Topology and parameter definition already allow metadata. Use a reserved `metadata.numerical_assumption` containing matching assumption identity/revision and category; enforce its exact typed shape in the assumption validator. Existing top-level topology provenance/state remain `inferred/unverified`. Do not use free-text metadata as executable authority: the new evidence declaration and policy-aware validator establish the linkage. No definition, topology, SourceRecord or output schema expansion is needed for this representation.

CLI `--allow-synthetic-regions` must generate `scientific_options.allow_synthetic_regions=true` (strict boolean). Require it at selection, pinning, runtime dispatch and region-model execution; default false for all public entry points. Preserve the new option in scientific configuration and hashes. Do not accept opt-in under `execution_options`, from evidence metadata or from a cached capability snapshot. Recompute availability from declarations plus permission, leaving `topology_trusted=False`; separately describe the result as executable under numerical assumptions. Source-validated calls without this option remain byte-compatible.

Compatibility: new readers accept old evidence/snapshots/packages unchanged, without inserting defaults into their serialized payloads. Old readers must reject new assumption evidence; this is intentional fail-closed incompatibility. No in-place rewriting of frozen inputs or source records. New assumption revisions produce new fingerprints/run identities. Keep v0.1 historical exact context shapes; new policy belongs inside existing configuration/assets, not extra exact context input keys. Migrating a caller means explicit re-selection/re-freeze with a new assumption record and permission, never relabeling old evidence.

## 5. Scientific invariants

The hypothetical topology is a declared **equivalent model**, not a claim about Jinko construction. For a minimal three-region experiment, declare three protected substrings in series, each with one equivalent region/branch, three nonoverlapping polygons covering the normalized module plane, and one bypass device per substring. Declare equivalent series-cell counts explicitly. PAN `NCelS=72`, `NCelP=2` must not be converted into undocumented physical branch connectivity. A one-branch equivalent can use full-module-equivalent current; explain that abstraction rather than doubling current because NCelP is two.

A candidate equal-series partition of the existing whole-module PVsyst model has 24 equivalent series elements per region; preserves photocurrent, saturation current, gamma, mu-gamma, alpha-sc, bandgap and reference irradiance/temperature; divides series and shunt resistances by three (including `r_shunt_0_ohm`), with the same shunt exponent. This follows series voltage scaling of the single-diode equation, not manufacturer evidence. It is only a candidate derivation to test, not an approved parameter dataset. Reverse resistance, voltage support, current ceilings, geometry and diode drop need independent explicit numerical assumptions; PAN does not determine them by this scaling.

Use existing `parameterization.py:PVSystRegionElectricalState` / `build_pvsyst_region_electrical_states`, `substring_reference.py:evaluate_series_branch_voltage`, `solve_parallel_branches_at_current`, `evaluate_protected_substring_at_current`, and `module_iv.py:assemble_nonuniform_module_iv`. The analytical substring reference is useful for closed-form transition fixtures, not a replacement production PVsyst model. Compare against the whole-module SDM/Level-1 path in `module_approximation.py:evaluate_level1_module_approximation` with identical effective irradiance, temperature, IAM and quality basis.

Proposed deterministic acceptance policy (version it and pin it; these tolerances are proposed, not existing rules):

| Invariant | Concrete acceptance experiment |
|---|---|
| Topology/geometry | Three complete protected substring mappings; exact region IDs/cell counts; summed active fractions and mapped area agree with one module within `1e-9` relative; no overlap/self-intersection, orientation transforms tested portrait/landscape. |
| Uniform IV consistency | Grid G = 200, 600, 1000 W/m²; T = 0, 25, 60 °C. Same physical irradiance and thermal basis, no quality/mismatch factors. Compare Isc, Voc, Vmp, Imp, Pmp against whole-module SDM, each within 0.5% relative (absolute floors 1e-5 A/V/W). At fixed currents through generating domain, three-region summed voltage matches whole module within 1e-4 V; isolate interpolation error and refine sampling deterministically before accepting. Also compare whole-module STC outputs to pinned PAN ratings under the existing module validation tolerances, without changing them. |
| Circuit conservation | Common series current; module voltage equals sum of substring voltages within 1e-6 V; parallel branch currents, if used, sum to substring current within 1e-6 A. No invented series/parallel manufacturer semantics. |
| Diode behavior | Uniform generating state has no active bypass. Shaded-region current sweep crosses the explicit clamp (ideal 0 V or constant negative forward drop); test below/at/above transition and current split. Do not require an unbypassed solution outside its explicit reverse domain. Parameterized-IV diode requests remain unsupported. |
| Signed power/losses | `P=V*I` with delivered current positive; preserve negative region power under reverse bias. Kirchhoff power reconciliation within 1e-5 W; diode dissipation nonnegative. Compare geometry → uniform-equivalent → nonuniform bypass-off → bypass-on → string/MPPT boundaries; signed deltas telescope without clamping or double-counting geometric loss. |
| Temperature/model relations | Region and module use identical reference bases and one module temperature; finite-difference temperature response at 24/25/26 °C agrees with whole SDM under the IV tolerances. Do not reinterpret per-°C coefficients, split alpha-sc with series voltage, or mix STC reference bases. |
| Domain/dark behavior | Finite curves, valid current/reverse support and existing dark/inactive MPPT semantics; explicit domain overflow rejects. No fabricated mixed-dark branch solution. |

If a grid or conservation test fails, the declaration is not executable. Whole-module IV agreement is necessary numerical evidence, never proof of substring construction or nonuniform real-world response.

## 6. Fail-closed safeguards

Reject absence of topology, regions, branch order, bypass coverage or any required parameter. Reject disagreement among topology metadata, definition metadata, evidence declaration, source records, revisions/digests and selected model IDs. Opt-in is permission to use a complete tested assumption, never permission to fill unknowns.

Reject numerical evidence claiming a manufacturer source for assumed facts, non-null validation record, trusted verification state or validated provenance. Original PAN references may support whole-module inputs but must be distinguished from the declaration source; do not reject honest inclusion of the PAN as contextual input. These are consistency checks, not cryptographic proof of source authorship: the repository cannot detect an entirely fabricated self-consistent historical source-validation record without external evidence. Do not claim otherwise.

Reject missing declaration revision/digest, changed payload without a new revision, definition revision mismatch, failed consistency results/recomputation, unsupported models and missing/false/nonboolean opt-in. Bind exact parameterization revision instead of choosing by parameterization ID alone on the new branch; preserve existing unique-ID resolution for old records.

For this pilot require `fallback_policy=fail_closed`: no geometric-only package may be reported as a completed Level-2 pilot. Integrity/provenance/permission failures on the new path must be classified as invalid input, preventing `run_detailed_dispatch`'s explicit lower-fidelity fallback branch. Keep existing source-backed fallback behavior unchanged. Proposed new finding codes should distinguish missing opt-in, invalid declaration, consistency failure and revision mismatch; they do not yet exist and must not be reported as current rule IDs.
