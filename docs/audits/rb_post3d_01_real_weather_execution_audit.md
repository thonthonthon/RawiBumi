## 4. Meteorology, timezone and provenance assessment

Canonical variables and units are explicit (`weather/core.py:13`, `CANONICAL_VARIABLES`): GHI/DNI/DHI/POA in W/m²; ambient/dew-point temperature in °C; wind in m/s; pressure in Pa; albedo/RH as fractions; precipitable water in mm; aerosol optical depth and Linke turbidity dimensionless. CSV accepts these canonical column names and coerces numeric input; unknown columns raise (`weather/csv/importer.py:156`). It is not a general arbitrary-column/unit mapper.

EPW uses pvlib's 1–24-hour normalization as canonical interval starts; hourly Wh/m² radiation converts to interval-mean W/m² with equal numerical values. RH divides by 100 and precipitable water multiplies cm by 10 (`weather/epw/importer.py:36–71`, `read_epw_weather_bytes()`). TMY3 parses right labels including 24:00, subtracts one hour, converts pressure/RH and documents source-time state samples (`weather/tmy3/importer.py:184`, `read_tmy3_weather_bytes()`). Its calendar classifier preserves a complete actual leap year or normalizes mixed-year typical-year labels to a recorded anchor (`:132`, `_normalize_source_calendar()`). A typical year is not an observed historical year.

Meteonorm infers cadence, shifts interval ends back by that duration and requires G_Gh and Ta (`weather/meteonorm/importer.py:190`, `read_meteonorm_dat_bytes()`; `:220–238`). Its source time-reference metadata is retained separately from canonical labels (`:309`, `build_time_semantics()` call); do not apply an extra inferred shift. PVsyst Standard CSV reads declared cadence and units (`weather/pvsyst/standard.py:54`, `_parse_time_step()`; `:107`, `_irradiance_to_w_m2()`), normalizes source/site fixed offsets, and separates whole-step timestamp shift from residual solar-evaluation shift (`:225–263`, `read_pvsyst_standard_weather_bytes()`). Wind, RH and water conversions are handled explicitly (`:287–319`). Numeric source sentinels are not generally proven safe merely because parsing succeeded: the EPW mapping, for example, copies numeric fields rather than explicitly translating every sentinel (`epw/importer.py:51`); inspect selected source missing-value conventions and QC findings.

Open-Meteo requests Unix time with GMT, explicit ERA5 and canonical-friendly units (`open_meteo.py:161`). Response timestamps parse as UTC; cadence must be continuous hourly; arrays must match length and units must be accepted (`:252–366`). Radiation preceding-hour labels shift back 3600 seconds, then convert to requested site timezone (`:407`). Instantaneous state variables at the original label are assigned to that preceding interval without interpolation, with per-variable metadata (`:417`). RH divides by 100 and hPa multiplies by 100. This is existing semantics, not a proposed alignment change. Requested date strings alone do not prove canonical local-year endpoints after this shift.

Canonical timestamps label starts; coverage end is last start plus duration (`weather/core.py:222`). Timeline evaluation uses midpoint plus an explicitly recorded solar offset (`engine/timeline/core.py:89–113`). CSV offset-aware values convert through UTC; naive IANA-zone timestamps reject ambiguous/nonexistent DST times (`weather/csv/importer.py:46`, `_parse_timestamps()`). EPW/TMY3/Meteonorm/PVsyst standard-time imports use fixed offsets, not DST inference. UTC elapsed chronology and local aggregation are separate: attribution groups the entire interval by its local start, without boundary proration (`attribution_energy.py:18`, `AGGREGATION_POLICY`; `:146`, `_assemble()`). Do not strip timezone information or substitute UTC month grouping.

Resampling rejects gaps/overlaps and noninteger ratios. Upsampling holds all variables constant; downsampling takes equal-duration means across complete groups and verifies irradiance energy preservation (`resample.py:86`). Native cadence survives, transformed origin becomes the frozen `opensimpv_derived` token, and QC is invalidated for rerun (`:46`, `_updated_weather()`). Temporal lineage and false-precision metadata distinguish source/provider-generated subhourly from RawiBumi disaggregation (`temporal.py:48`, `_lineage_from_input()`; `:153`).

GHI and ambient temperature are base QC requirements (`qc.py:206`). Wind may be optional to base QC, but thermal execution requires complete nonnegative wind when Uv is nonzero; Uv=0 permits recorded `not_required_uv_zero` (`engine/thermal/pvsyst.py:60`, `calculate_pvsyst_temperature()`; `:111–140`). Solar uses weather latitude/longitude, optional elevation defaulting to zero, and pressure from complete weather or standard atmosphere (`engine/solar/position.py:183`). No automatic site/weather coordinate agreement gate is established here; compare those values before launch.

`complete_irradiance()` preserves valid source DNI/DHI, derives one missing component analytically where appropriate, uses explicit low-sun protection, and requires an explicitly selected Erbs/DISC/DIRINT model when unresolved daylight components remain (`completion.py:196`). This is declared component completion, not permission to silently replace missing GHI or temperature. Solar-aware QC combines base, physical-limit, component-closure and time-reference checks; clear-sky screening requires an explicit reference and is not implicitly enabled (`weather/validation/solar_qc.py:634`). Night irradiance/time-reference anomalies can be warnings (`:429`, `_time_reference_findings()`), so a completed run with warnings needs review.

Raw byte SHA-256 and source identity enter source-file metadata (`core.py:124`); provider snapshot storage is content-addressed and reads check the hash (`snapshot_store.py:20`). Provider manifests retain request, raw digest, normalized-weather fingerprint and normalization metadata (`open_meteo.py:484–719`). The weather revision store preserves metadata/series but does not itself recheck raw snapshots at load.

Revision resolution checks project/configuration pins and resolved identities (`canonical.py:331`). Generic canonical input hashing covers selected dataset/series plus scene, electrical, module, inverter, configuration and engine (`:1527`, `_input_hashes()`). Detailed context instead binds full supplied weather metadata and full series logical hash along with scientific configuration, frozen selection and component revisions (`detailed_dispatch.py:251–263`); the selected period is bound by configuration. Execution/storage options are excluded by `:27`, `scientific_configuration()`. Detailed reproduction records selected dataset metadata while taking the full-series hash from context (`detailed_downstream.py:266–287`). Do not equate these differently scoped weather hashes or redefine them during validation.
