## 5. Execution authorization trust chain

### 5.1 Concrete witness and rejection mechanism

**Proposed internal type**, in authorized `detailed_inputs.py`, `AssumptionAuthorizationWitness`: canonical scientific-configuration bytes plus their expected semantic SHA-256; canonical FrozenDetailedSelectionSnapshot record (payload, payload hash, scientific hash); exact five-key module input hash; selected module revision/evidence ID/parameterization revision; policy and solver/engine identity. This is transport outside the historical five-key payload, not a new persisted envelope property. Its authority is the validated scientific configuration and its exact association with the selected frozen inputs. A raw optional boolean, a private constructor, a caller-supplied `passed` field or a claimed witness digest is never sufficient.

New `validate_assumption_authorization_witness` in I must:

1. Recompute canonical configuration and selection hashes; use existing snapshot replay/identity checks; reject unknown or missing witness fields, noncanonical bytes and module payload mismatch.
2. Require the module/evidence/definition/source content to be the exact selected content in that frozen registry (not IDs alone). Validate full configuration schema/model/fidelity/fallback semantics, strict `scientific_options.allow_synthetic_regions is True`, no permission under execution_options, supported Level 2 and selected model family. Scientific configuration strips execution options for identity; validate original execution options before stripping so a misplaced flag cannot silently authorize.
3. Run all source/metadata/revision/digest and physical acceptance checks over those immutable inputs. Never trust transported numerical-success booleans. Cache only results computed by these validators, indexed by complete immutable identities (§12); if absent recompute, including in a new process.
4. When an expected canonical configuration/selection is supplied by dispatch/backend/verifier, require exact canonical-byte and fingerprint equality to it. Reject a witness for another configuration even if its own hashes and True flag are valid.

`pin_detailed_module_inputs` gains default-deny keyword `authorization_witness=None` and a supported way to derive it from validated `scientific_configuration`, `frozen_selection` and selected module binding. It never creates permission from metadata. `DetailedModuleInputSnapshot` gains an optional immutable witness transport field with default None (legacy two-argument construction remains valid). `replay()` retains its zero-argument signature; for v0.2 it validates that witness and exact module membership using the new helper. **An externally constructed snapshot with only allow_synthetic_regions=True, or with a witness whose config was stripped/tampered, is denied.** Config false cannot be overridden by any transport flag. Legacy replay executes the unchanged v0.1 validation path and produces identical bytes/hash.

This is cryptographic **content binding**, not a new identity-signature system. Someone may deliberately create a new valid scientific configuration with True and new corresponding fingerprints; that is the explicitly authorized scientific opt-in, not permission to relabel an existing false-config run. The contract defines no separate human/account signing authority. A completely rewritten, self-consistent package is a new scientific identity; the verifier checks it against run/manifest identities and semantic gates, not against a nonexistent external signature. Do not describe a SHA-256 digest as authentication of a manufacturer or person.

Replay must not recursively call itself during acceptance. Separate structural/identity replay from execution authorization internally: `FrozenDetailedSelectionSnapshot.replay` verifies selection/assets and evidence structure without authorizing execution; `I._validate_payload` accepts an internal validation phase. New P acceptance builds region states with structural binding already checked, through a non-authorizing internal path, then emits a computed acceptance result. Public `P.build_pvsyst_region_electrical_states` remains default-deny for v0.2. The private path performs numerical evaluation only for acceptance, cannot export an execution permit, and never replaces production physics. In R, factor the existing post-state-construction body (current ceiling, source identity, endpoint holder and V(I) closure at :134–350) into a new internal `_build_series_model_from_checked_states` helper. Factor P state construction similarly into new internal `_build_region_states_from_checked_inputs` at :653–end; it retains all current map/local-state/domain checks, and the public builder performs evidence/authorization checks before calling it. The acceptance evaluator calls it only after independent structural/source/revision validation. Neither private helper accepts a boolean as scientific authority. The witness validator consumes the result after explicit configuration permission has been checked. This prevents circular validation between a gate, adapter and public binding checks.

## 12. Performance and replay implications

Primary acceptance is 15 fixed-current evaluations plus three diode setups, secondary conservation arithmetic, bounded bypass bracket states, three fixed-G temperature setups with continuous MPP precision evaluation, characteristic curves and domain probes. Cost is per unique immutable numerical candidate, not per module instance × interval × replay. No cost/runtime/RSS measurement was executed; these are operation-count expectations, not benchmark claims.

Proposed immutable cache key: full five-key canonical module payload digest; full source registry digest; topology/definition/evidence/declaration/consistency digests; configuration scientific digest and frozen selection scientific digest; selected model IDs/versions, solver ID, engine/pvlib implementation version; primary policy ID/version plus fixed secondary-policy constants/version. Record-based digests are **recomputed** before cache lookup. Revision IDs alone, parameterization ID, mutable True, submitted passed and raw object identity cannot key or seed acceptance. A source_notes/author/rationale/limitation/policy/model change invalidates the key. Cache stores only validated results produced by the acceptance evaluator, never transported claimed success.

Use bounded in-process cache in I/P at authenticated pin/resolve; replay performs canonical byte/digest checks and consults the separately memoized witness validation plus acceptance result; first-key structural witness cost and repeated hashing cost are detailed below. New immutable key triggers evaluation; exact repeated key does not. Process initializer independently validates or recomputes once per unique key and keeps local immutable context; workers never deserialize an arbitrary successful cache entry as authority. Independent package verification uses a fresh local cache, recomputes once per unique selected candidate, shares only within that verification operation. Avoid repeated expensive gates at every downstream area/rating/quality replay or interval counterfactual.

Witness validation has its own replay cost, separate from the physical gates. The unchanged downstream loop replays per module for quality (:187), width and height (:217, two calls) and installed power (:229); B replays for history (:268) and worker context (:384), and T replays for attribution context (:234). That is at least seven module replays per module in a combined path, or at least 1,330 for 190 modules, before extra chunked-attribution calls. A naive v0.2 witness replay would parse/canonicalize and hash the full config/frozen selection, run Frozen replay/A selection checks and read JSON schemas from disk through I._schema:50 on each call. Its cost scales with the full witness size and selected-registry size, not just three regions, and must not be called merely cheap cross-bindings.

Add a second bounded per-process memoization table to I.validate_assumption_authorization_witness: key `(module scientific_input_sha256, configuration semantic sha256, frozen-selection scientific sha256, full frozen payload sha256, policy/solver/engine identity)` with the exact immutable canonical config/selection/witness bytes retained and checked against the cache entry. Recompute byte digests and require canonical-byte equality to the validated entry before a hit; cache keys supplied by caller are never trusted. Cache hit skips JSON parse, schema disk reads, Frozen replay, source/linkage checks and gates already validated for those exact bytes. Every expected-run B/T/D comparison still executes on a hit, and every operating-state domain check remains active. Miss performs complete structural/semantic witness validation and populates cache only on success. Changed bytes cannot reuse a successful entry even if claimed hashes are unchanged. Bounded eviction may cause revalidation, never permission reuse; size entries by bytes as well as count to avoid copying the whole frozen registry once per module instance. Share immutable canonical witness bytes for modules using the same config/selection; store module-specific membership binding separately. Do not retain decoded mutable dictionaries as acceptance authority. Fresh worker processes validate once per unique key locally; verifier uses an isolated cache with no inherited runtime entries.
